REPORTE DE PENDIENTES PARA MODO OFFLINE (PWA)
Proyecto: medicalweboffline-main
Fecha: 2025-10-26

1) PORCENTAJE DE AVANCE ACTUAL
- Soporte offline global (PWA con Service Worker + Manifest): 0% (no existe sw.js ni manifest)
- Precarga de contenido para offline (localStorage): 70% (funciona, pero con riesgos por uso de ES Modules via Blob)
- Persistencia de datos local (usuarios, operaciones, pacientes): 85% (localStorage completo en modelos)
- Navegación SPA offline (carga de páginas desde localStorage): 65% (funcional, pero dependiente de precarga y con riesgo por imports ESM)
- UX de estado de conexión: 70% (banner UI existente, pero consulta a recurso externo)
- Seguridad/autenticación offline: 75% (JWT simulado + fallback legacy, correcto para offline local)
- Infraestructura de servidor local: 90% (server.js correcto para servir estáticos, falta MIME para manifest y headers PWA)

Porcentaje de avance global estimado: 62%

2) HALLAZGOS CLAVE
- No hay Service Worker ni Manifest Web App: la app no es PWA y no tiene caché controlado para recursos en modo sin conexión real.
- La estrategia actual carga controladores desde localStorage usando Blob + type="module". Los controladores importan otros módulos (ESM). Al ejecutarlos desde un Blob, los imports relativos pueden fallar (base URL blob:), rompiendo el modo offline.
- La UI de conexión consulta https://www.google.com/favicon.ico. En redes restringidas o sin internet esto puede fallar o generar ruido; mejor usar un recurso local cacheado por el SW.
- La precarga en login guarda HTML y JS en localStorage. Con Service Worker, esto puede simplificarse: los módulos se cargan normalmente (import/export) y el SW los sirve del caché offline.
- Rutas absolutas tipo "/menuInicio.html" dependen del origen actual. En PWA con SW es válido, pero conviene mantener consistencia de rutas y scope del SW.

5) PRUEBAS RECOMENDADAS (POST-IMPLEMENTACIÓN)
- Iniciar server local, abrir index.html, hacer login online, verificar que el SW se instala y se rellena el caché (Application > Cache Storage en DevTools).
- Desconectar internet (manteniendo el server local) y refrescar: la app debe cargar completa gracias al SW. Navegar entre categorías desde el menú; los controladores deben resolver sus imports (sin Blob).
- Borrar manualmente las claves de precarga en localStorage y comprobar que el SW aún sirve las páginas/JS desde caché (la app debe seguir funcionando offline).
- Cambiar una versión del SW (CACHE_NAME) y verificar que hace limpieza de caches antiguos y se actualiza correctamente (skipWaiting/clientsClaim).
- Probar la UI de conexión con el nuevo recurso local; verificar que cambia a offline/online según estado real.

6) NOTAS Y RIESGOS
- La ejecución de controladores ESM desde Blob con type="module" es frágil por las importaciones relativas; por eso se instruye migrar a import() estándar con rutas reales y delegar el offline al SW.
- El almacenamiento en localStorage es suficiente para este alcance. Si crece el volumen de datos, evaluar IndexedDB en el futuro.
- Evitar dependencias externas (CDN) no cacheadas por el SW para mantener robustez offline.
